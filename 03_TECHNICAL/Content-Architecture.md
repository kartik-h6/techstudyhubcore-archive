# Content Architecture

## The hierarchy adopted

**[FACT]** The project increasingly adopted a structured content hierarchy:

```text
Program
→ Semester / Class
→ Subject
→ Unit / Chapter
→ Content Page
→ Resources
```

## The principle

> **Do not make the PDF the architecture.**

Instead, a topic should have a permanent page:

```text
Permanent topic page
+
PDF
+ video
+ diagram
+ PYQ (previous-year question)
+ external resource
```

with those items attached as *resources* rather than being the structure itself.

## The shift

**[LESSON]** This was an important shift from *file-centric content* to *knowledge architecture*.

## Why it matters

**[LESSON]** Content generated before the architecture is proven becomes content that must later be restructured. Volume is not a substitute for structure.

See `06_PRODUCT/Validation-Lessons.md` and `02_PROJECTS/Pharmacy.md`.
