# Validation Lessons

## The core problem

**[LESSON]** The project built before validating. The problem was assumed from personal experience and never tested with real users before significant building began.

## The falsification questions

Adopted as a discipline for future work:

- What would prove this wrong?
- What metric determines whether I continue?
- How can I test this in seven days?
- What is the opportunity cost?
- If I could build only one thing, what should it be?

## Activity vs traction

**[LESSON]** Commits, pages, deployments and experiments are **activity**. They are not automatically proof of sustained user value.

> Don't confuse activity with traction.

## Validate before scaling

**[LESSON]** Generating pages is not proof that people need those pages.
