# TrailCode → TechStudyHubCore

## What TrailCode was

**[FACT]** TrailCode was an early prototype and learning artifact — the first working attempt at an educational website.

It was built around **HTML and JavaScript**, with **client-side rendering** concepts.

It included views and functions such as:

- home
- notes home
- semester
- subject
- about

## What TrailCode taught

**[LESSON]** TrailCode was useful because it showed how an educational website could become *interactive* — how content could be navigated as a system rather than read as a document.

## What TrailCode exposed

**[FACT]** It also exposed important limitations. It contained prototype-level concepts such as:

- hardcoded admin credentials
- localStorage-based administration
- client-side assumptions about trust

**[LESSON]** These were not suitable as production security.

Key lessons drawn directly from TrailCode:

- localStorage is not a secure backend
- frontend authentication is not sufficient authentication
- hardcoded credentials must never be used for real production security
- authorization must happen server-side
- prototypes should not automatically become production architecture

These mistakes are preserved deliberately. They are part of what was learned — see `04_SECURITY/Prototype-Security.md`.

## The transition

**[FACT]** The project evolved from the TrailCode prototype into the broader TechStudyHubCore ecosystem.

The name change reflected a change of intent: from a coding project toward an education-facing identity.
